# 07 · 轨迹插值（trajectory）

> 对应 HANDOFF §12 第 7 份、缺陷 #1/#2/#3
> 产出：`core/trajectory.py`
> 一句话：**取代幂缓动，且段与段之间速度不断。**

---

## 1. 为什么禁用幂缓动（数学上必须出局）

旧代码 `t ** 0.55`：

```
f(t) = t^0.55
f'(t) = 0.55 · t^(-0.45)
t → 0 时 f'(t) → +∞
```

导数在起点发散 = 第一帧速度无穷大 = **176 mm 单帧瞬移**的直接来源。这不是「调参没调好」，是这个函数族本身不能用。

`t*t` 和 `smoothstep` 没这个问题，但它们**两端速度为 0**：每段都要「起步—加速—减速—停」，这就是「一顿一顿」的来源。

所以需要的是：**端点速度可以不为 0 的曲线**。

---

## 2. 三次 Hermite（主力，用于段内）

给定起点 `p0`、终点 `p1`、起点速度 `v0`、终点速度 `v1`、段时长 `T`，参数 `t ∈ [0,1]`：

```
h(t) = (2t³ − 3t² + 1)·p0
     + (t³ − 2t² + t)·T·v0
     + (−2t³ + 3t²)·p1
     + (t³ − t²)·T·v1
```

属性（都必须靠测试证明，不是靠推导）：

| 属性 | 检查 |
|---|---|
| `h(0) = p0` | 起点对 |
| `h(1) = p1` | 终点对 |
| `h'(0) = v0` | 起点速度对 |
| `h'(1) = v1` | 终点速度对 |

**`v0` / `v1` 是「每秒多少单位」，不是「每段」。** `T` 已经在式子里，不要重复乘。

---

## 3. 段间速度传递（**这是本份文档真正要解决的问题**）

一段接一段时，如果每段的 `v1` 和下一段的 `v0` 不相等，接缝处速度突变 = 一次顿挫（C0 连续、C1 不连续）。

### 3.1 规则

```
v_out(i) ≡ v_in(i+1)                       # 硬约束，不许各写各的
```

### 3.2 内部节点的速度怎么取

对第 `k` 个关键帧（前后各有一段）：

```
v_k = (p_{k+1} − p_{k−1}) / (T_k + T_{k+1})
```

（这是 Catmull–Rom 的中心差分，`T` 用两段时长之和。）

**为什么不是前后速度平均**：平均在「先快后慢」时会得到偏快的速度，导致过冲。中心差分按时间加权，过冲最小。

### 3.3 端点

| 位置 | `v` |
|---|---|
| 动作起点 | `0`（静止起步）或 LLM/族指定 |
| 动作终点 | `0`（静止收势）或指定 |

**允许非零端点**是关键：接续上一段动作时，起点速度 = 上一段的终点速度，这样两段动作之间也不顿。

### 3.4 速度方向反转怎么办

如果 `v_k` 和前后两段的方向都相反（比如「挥手到最高点再往下」），中心差分会在最高点给出一个**近似为零**的速度——**这恰好是对的**（顶点速度应为 0）。

如果强行给非零，会「冲过头」，那是另一种顿挫。**不要手动改顶点的速度**，除非你确定要过冲。

---

## 4. 五次曲线（只用于摆动相）

摆动腿的抬脚必须**端点速度、端点加速度都为 0**（gait-guide 的硬要求），否则落脚会「砸地」。

```
s(t) = 6t⁵ − 15t⁴ + 10t³
```

`s'(0)=s'(1)=0`，`s''(0)=s''(1)=0`。只用于 G 的摆动段，**不用于姿态段**（姿态段用三次 Hermite，否则过度平滑显得没劲）。

---

## 5. 缓动只影响「时间重映射」，不影响「曲线形状」

如果需要「慢起快收」，**不要换曲线族**，而是对 `t` 做一次重映射：

```
t' = ease(t)      # ease 必须满足 ease(0)=0, ease(1)=1, ease'(0),ease'(1) ∈ [0, ∞)
then h(t')
```

允许的 `ease`：

| 名字 | 形式 | 端点导数 |
|---|---|---|
| `linear` | `t` | 1, 1 |
| `ease_in_out` | `3t² − 2t³` | **0, 0**（只在「两端都要停」时用） |
| `ease_in` | `t²` | 0, 2 |

**禁止** `t^p`（p≠1 且 p<1 时导数为无穷）、`sin` 之类周期函数（端点导数不可控）。

---

## 6. 验收

**必须导出 CSV，画速度曲线**——运行时不 bake Action，没有 Graph Editor 可看（HANDOFF §8.5.1）。

`tools/dump_trajectory.py` 输出：

```
t_s, bone, channel, pos, vel, acc
```

检查项：

| 检查 | 阈值 | 说明 |
|---|---|---|
| `h(0)` / `h(1)` 与端点 | 误差 <1e-6 | 端点对 |
| `h'(0)` / `h'(1)` 与指定 `v` | 误差 <1e-4 | 速度对 |
| **接缝处速度跳变** | `|v_out(i) − v_in(i+1)| < 1e-6` | C1 连续 |
| **速度曲线是否有「平台」** | 不允许出现「连续 ≥3 帧 vel≈0 且不在端点」 | 旧项目的「每段重新起步」 |
| **最大角速度** | ≤ 12°/帧 | 与 `max_deg_per_frame` 谓词一致 |
| 二阶差分 | 不出现单帧尖峰 > 10× 中位数 | 隐式抓余下的抖动 |

第 3、4 条是 P0 的核心验收：**接缝不跳、没有 0 速平台**。

---

## 7. 风险

1. **`T` 单位**：`v` 是「每秒」，`T` 是「秒」。仿真时 `T = 帧数 / fps`。这里最容易差 30 倍。
2. **中心差分的边界**：`k=0` 和 `k=n` 没有前后段，必须用端点规则，不能套公式（会越界）。
3. **角度插值**：`p` 是标量（每个通道单独插），不要对四元数直接做 Hermite——四元数要用 slerp（那是 `binder` 的事，`trajectory` 只给欧拉角/通道值）。
