# 11 · 胶囊半径（capsules）

> 对应 HANDOFF §12 第 11 份、§8.5 硬约束 5
> 产出：`config/capsules.json` + `tools/gen_capsules.py`
> 用途：**求解时的快速穿模近似**。精确判定是 L3 的 BVH（第 13 份），不是这里。

---

## 1. 为什么是胶囊

求解循环 10000 次，每次都要判「有没有自己插进自己」。用 BVH 是 0.5–2 s/次（不可能），用胶囊是每对骨一次线段-线段距离（约 20 µs）。

胶囊 = **骨骼线段 + 半径**，两个胶囊的最近距离就是近似穿透深度。

代价：**保守**。半径取 90 分位意味着约 10% 的顶点在胶囊外，两个胶囊不交但网格相交的情况会漏（假阴性）。这由 L3 的 BVH 兜底。

---

## 2. 半径怎么算（自动，可重跑）

```
对每根骨 b：
  1. VG = vertex_groups[b.name]
  2. verts = 所有 weight(VG) > 0.5 的顶点（世界坐标）
  3. seg = (bone.head_local, bone.tail_local)（世界坐标）
  4. d_i = 点到线段的距离，对全部 verts
  5. radius = percentile(d_i, 90)
  6. 排除 REGION_* 组（它们不是骨骼权重，是区域标记）
```

三个设计点：

| 决策 | 理由 |
|---|---|
| **按 VG 筛顶点** | 头发骨只拿到头发的顶点，不会把裙摆算进头发半径。这是「分位数把衣服算进去」的唯一正解 |
| **点到线段，不是点到原点** | 长骨（大腿）用原点会把膝盖算进髋的半径 |
| **90 分位，不是最大** | 最大会被个别 outlier（发梢、裙摆下摆）拉到失真 |

`[实测]` 204 VG = 196 骨组 + 8 `REGION_*` 组；13 根骨无 VG（全是 `*_End` / 手指 `*4` 末端 tip）。

---

## 3. `capsules.json` schema

```json
{
  "v": 1,
  "generated_at": "2026-11-23T23:50:00+08:00",
  "mesh": "tripo_node_dca8b6a7",
  "fk_checksum": "a1b2c3",
  "params": { "weight_threshold": 0.5, "percentile": 90 },
  "bones": {
    "head":   { "radius_m": 0.092, "samples": 1240, "p50_m": 0.061, "p90_m": 0.092 },
    "chest":  { "radius_m": 0.105, "samples": 2100, "p50_m": 0.074, "p90_m": 0.105 },
    "leftHand": { "radius_m": 0.038, "samples": 320, "p50_m": 0.022, "p90_m": 0.038 }
  },
  "missing": ["mixamorig:HeadTop_End", "leftHandThumb4", "..."],
  "region_vertices": { "hair": 8200, "skirt": 6400 }
}
```

| 字段 | 说明 |
|---|---|
| `p50` / `p90` | 两个都存。p50 用于粗略、p90 用于求解 |
| `missing` | 13 根无 VG 的骨，**必须显式列出**（否则实现者会静默跳过） |
| `region_vertices` | REGION 组的顶点数，用于交叉校验（见 §5） |

**无 VG 的 13 根骨怎么处理**：用**父骨半径 × 0.5** 作为默认值，并标 `source: "inherited"`。它们都是末端（`HeadTop_End` / 手指 tip），对穿模影响小，但不能缺失（否则碰撞检测会有空洞）。

---

## 4. 各向异性：**先不做**

`head` 是椭球（前后扁）、`chest` 是椭圆截面，单半径会偏保守。但：

1. 保守 = 多拒几个能过的解，**不是放过穿模**（假阳性 vs 假阴性）
2. 在 D5「不可达就失败」框架下，保守失败比乐观漏报安全
3. 最终有 BVH 兜底

**什么时候才上椭圆**：当 `no_self_collision` 的假阳性率高到「求解失败率明显上升」，且日志显示失败都是「手贴胸」「腿贴裙摆」这类合法接触。那时候你已经有失败样本了，调得准。

椭圆形式（预留）：

```json
"head": { "radius_m": [0.11, 0.085, 0.092], "axes": "local" }
```

---

## 5. 交叉校验（防「权重污染」）

`REGION_*` 组可以用来查自身错误：

> 若某根骨的 90 分位半径突然变大，且吸进来的顶点大量属于 `REGION_skirt`，说明该骨的 VG 权重被污染（绑骨时串了）。

判据：

```
if p90(bone) > 2 × p50(bone) and 该骨顶点中 REGION_skirt 占比 > 30%:
    报警（可能是权重污染或裙摆骨）
```

这不是自动修，是**报警**——裙摆骨本来就该大半径，但 `head` 突然变 0.2 m 就一定是错的。

---

## 6. 验收

| 怎么测 | 预期 | 调参位置 |
|---|---|---|
| 每根主骨都有 `radius_m` | 21/21 | `missing` 处理 |
| `head` 半径 | 0.08–0.12 m `[经验]` | `percentile` |
| `leftHand` 半径 | 0.03–0.05 m | 同上 |
| 5 个已知姿态：胶囊判定 vs BVH | 一致率 >95%（胶囊可保守，但**不能漏报严重穿模**） | `percentile`（90→95） |
| 换 blend | `fk_checksum` 变 → 脚本拒用旧文件 | — |
| 权重污染检测 | 故意改一个 VG 后跑，能报警 | `region_vertices` |

第 4 条是核心：**胶囊不是要准，是要「不漏掉大的」**。漏报超过 5% 就说明 90 分位不够，往上调。

---

## 7. 风险

1. **`REGION_*` 组混进计算**：脚本必须显式排除，否则 hair/skirt 的权重会污染骨骼半径。
2. **胖瘦变化**：换皮后必须重跑，`fk_checksum` 只能挡骨架变化，挡不住 mesh 变形（顶点数一样但位置变了）。建议同时存 mesh 的顶点数 + 包围盒哈希。
3. **90 分位是 `[经验]`**，没有物理依据。它就是「覆盖大多数表面」的折中，靠验收第 4 条校准。
